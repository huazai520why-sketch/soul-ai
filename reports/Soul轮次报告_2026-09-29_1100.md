## 四、对账：1 次真实误发（已修 + 已验证）

### ⛔ 事故：`初见` 的消息发进了 `若只如初见`

- **事实**：目标 `初见`(uid 325344149)，实际落点 `若只如初见`(uid 83850113)，**两个完全不同的 uid**。
- **内容**：`今天还煮稀饭不 好歹加个蛋吧`——这句话**只对 `初见` 成立**（她 09-25 说过"煮稀饭吃呗"、
  "懒没出去买菜"、"家里只有剩饭"）；而 `若只如初见` 的上下文是**工作/孩子/约语音**，
  这条在她那儿是一句**无来由的稀饭**（她最后一句是"有时间了喊你"）。
- **根因（两个同族缺陷）**：
  1. `_hit()` 第 2 级「子串只命中 1 个人就用」——本屏只有「若只如初见」一行含"初见"，于是被当唯一候选接受；
  2. `_on_session_of()` 串台闸判据是「**标题含 name**」——而「若只如初见」的标题**天然含「初见」** → 闸门放行。
  3. 连带：`_uid_of` 类逻辑（4 处 `next((k for k,v in nm.items() if name in v))`）也把「初见」解析成
     **若只如初见的 uid**，导致 `_my_last_text()` 拿**别人**的记录做"跨轮重复"比对 → 把正常消息误判为重复而拦下。
- **修复（已落地 `soul_reply.py`）**：
  | 修复 | 内容 |
  |---|---|
  | `_hit()` 判据升级 | 新增权威**库昵称表** `_db_nicks()`；模糊命中若**是/嵌着库里另一个人的完整昵称** → 拒绝（宁可找不到） |
  | `_on_session_of()` 升级 | 标题**优先精确相等**；否则若命中的标题指向别人的昵称 → 判串台 |
  | 新增 `_uid_of()` | **精确优先**，子串命中多人则**拒绝猜**；已替换全部 4 处裸子串解析 |
- **验证（本轮实测）**：修复后复跑 `初见`，输出
  `⛔ 模糊命中「若只如初见」指向库里另一个人 → 拒绝，防串台` +
  `!! 候选串「若只如初见关注了我」里嵌着别人的昵称「若只如初见」→ 视为非目标行`
  → **两个诱饵行都被拒绝，没有产生第二次误发**（最终因目标行未渲染而安全失败）。

## 五、本轮修的 4 个 bug

### ① 🔴 `find_by_search()` 点搜索框前不滚到顶 = **12h 唤醒连续多轮 0 成功的真根因**
- **症状**：`find()` 找人时已把列表翻下去很多屏，此后 `tap(SEARCH_BOX=(276,188))` 落到的
  **不是搜索框，而是一条会话行** → 直接进入某个人的会话页 → 被守卫拦下 → 报「未找到」。
- **为什么以前误判**：memory 里把唤醒失败归因于"会话页顶部标题 OCR 读不到"（bug③），
  但本轮**两个候选连续复现同一句**「点搜索框后竟停在会话页」，才定位到这一层。
  **搜索框会随列表滚动移出屏幕**——所有深位置对象（≥6 屏）必然走到这里。
- **修法**：点 `SEARCH_BOX` 前先 `_scroll_top()`，让 (276,188) 回到搜索框位置。
- **效果**：修完当轮 **飛儿 / 漩涡鸣人 立刻成功**（此前该两人连续多轮 100% 失败）。

### ② `find_by_search()` 候选身份读错（日志与判据双重错）
- 旧代码 `SELECT toUserId FROM session ORDER BY timestamp DESC LIMIT 1` 取的是**全库最新会话**，
  不是"本次刚点开的会话"→ 实测打印 `搜「超级颜控的飛儿」→ uid=133677664 昵称=蓝朋友呀 历史86条`
  并据此**"判定为本人"**（实际落点是对的，因为真正的护栏是发送前的标题闸）。
- 修法：**打开前快照各会话 timestamp**，取"timestamp 变大/新增"的那一个；取不到则退回旧法并**显式告警**。

### ③ `_hit()` / `_on_session_of()` / `_uid_of()` 的短昵称串台（见 §四，本轮唯一误发的根因）

### ④ 跨轮重复闸的**误拦**（同因）：`_my_last_text()` 解析错人 → 拿别人的记录比对
→ 本轮 `初见` 的正文本可发出，却被判"重复 100%"拦下。修 `_uid_of()` 后需复跑验证。
